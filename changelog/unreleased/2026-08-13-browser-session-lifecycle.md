# Penguin Browser reports disconnected extension sessions without crossing installation boundaries

Extension-bound sessions now stay visible as `DISCONNECTED` when their installation is not connected. Execute and reset return the same structured `409 SESSION_EXTENSION_DISCONNECTED` response whether the disconnect is observed before an operation or occurs while it is reconnecting. The message stays neutral because a stopped MV3 worker or network interruption can be temporary; a reconnect with the same installation identity restores the session automatically.

Removing and loading the unpacked Chrome extension again creates a new installation identity. The old session is not silently deleted, because its state and diagnostics still matter, and it is not automatically migrated by matching browser, profile, account ID, or email labels, because multiple installations can share those labels. Legacy extension builds—or workers that cannot persist an installation ID—are connection-scoped and must be rebuilt/reloaded or recover extension storage before creating persistent sessions. If the original installation will not return, delete the old session and create a new one after authorizing a tab in the current extension.

The Chrome extension release sequence remains independent from the Travel Agent product and browser CLI versions. Its private package metadata now matches manifest `0.0.107`, with an explicit release-baseline guard and contributor documentation preventing alignment drift or accidental rollback. The extension continues to report browser CLI `0.4.0` separately as its relay compatibility-build version.
