# The trip page: a journey's identity, its conversations, and the itinerary

`/trips/:tripId` shows what a journey is and what the agent has written for it. This is P4 of
`tasks/trip-container.md`.

Details:

- The page renders the trip's identity line, its conversations (each opening the chat), and
  `itinerary.md` as markdown, using the same renderer the chat uses.
- The itinerary is **read-only here**. That file belongs to the model; this application renders
  it rather than editing it, which is the same ownership split `trip.json` has in the other
  direction.
- A trip with no itinerary yet is an ordinary state, not an error: `GET
  /api/trips/:tripId/itinerary` answers 200 with `exists: false`, and the page says the agent
  writes it as the work produces something worth keeping. A folder the person moved away answers
  the same way, and `dirExists` is what distinguishes the two on screen.
- The folder's absolute path is shown deliberately — a trip is a folder its owner can open, back
  up and keep after uninstalling this application.
- Rename and delete live here. Delete says in words what it does: the conversations stay (they
  become loose questions) and the folder on disk is never removed.
- The sidebar's trip header gains the link to it.
- **Not built, as decided on 2026-08-26:** any booking or receipt record. The run stops at the
  payment page and cannot observe whether payment happened, so a stored "booked" state would be
  a guess.

Also fixed here: three server skill-API assertions that still expected a two-skill library after
`trip-workspace` was added in P3 — caught by running every package's suite rather than only the
ones the change appeared to touch.
