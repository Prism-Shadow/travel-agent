## Package boundary notes

- `@travel-agent/transaction` is the current travel-specific transaction-safety package. It owns write-ahead journaling, commitments, drift detection, checkpoints, escalation, handover, payment capability semantics, and `submitBooking`.
- `packages/travel-domain/` is not part of the current tree. Travel-domain logic that remains relevant has been folded into `packages/transaction/` or removed.
- `packages/transaction/` is still structurally useful if the product continues to guard irreversible actions such as booking or payment confirmation, because it gives server/web/desktop/browser tooling a shared vocabulary for those actions instead of duplicating transaction types in each layer.
